# LLM Wiki 패턴 — Karpathy 원안과 이 스킬 묶음의 변형

## 원안 요지 (Andrej Karpathy, "LLM Wiki" gist, 2026)

**문제**: 문서를 RAG 로 붙이면 LLM 은 질문할 때마다 원본 조각을 다시 찾아 처음부터 지식을 재구성한다. 아무것도 쌓이지 않는다. 다섯 문서를 엮어야 하는 미묘한 질문이면 매번 다시 엮는다.

**아이디어**: LLM 이 원본과 사용자 사이에 **지속되는 위키**(서로 링크된 마크다운 파일 묶음)를 점진적으로 만들고 유지한다. 새 원본이 오면 색인만 하는 게 아니라 읽고, 핵심을 뽑고, 기존 위키에 통합한다 — 엔티티 페이지를 고치고, 주제 요약을 다시 쓰고, 새 자료가 옛 주장과 모순되면 표시한다. 지식은 한 번 정리되고 **계속 최신으로 유지**된다. 위키는 복리로 쌓이는 산출물이다.

**역할 분담**: 사람은 원본을 고르고, 분석 방향을 정하고, 좋은 질문을 하고, 의미를 생각한다. LLM 은 그 밖의 전부 — 요약, 상호참조, 정리, 장부 관리. 사람이 위키를 버리는 이유는 유지 부담이 가치보다 빨리 커지기 때문인데, LLM 은 지루해하지 않고 한 번에 파일 15개를 고칠 수 있다.

**3계층**
1. **원본(raw sources)** — 사람이 모은 문서. 불변. LLM 은 읽기만 한다. 진실의 원천.
2. **위키** — LLM 이 생성한 마크다운(요약·엔티티·개념·비교·종합). LLM 이 전적으로 소유한다. 사람은 읽고, LLM 은 쓴다.
3. **스키마** — `CLAUDE.md` 같은 에이전트 지침 문서. 위키 구조·관례·워크플로를 정해 LLM 을 범용 챗봇이 아니라 규율 있는 위키 관리자로 만든다. 사람과 LLM 이 함께 키워 간다.

**연산**
- **Ingest** — 새 원본을 넣으면 LLM 이 읽고 핵심을 사용자와 짚은 뒤, 요약 페이지를 쓰고, index 를 고치고, 관련 엔티티·개념 페이지를 갱신하고, log 에 남긴다. 원본 하나가 10~15 페이지에 닿을 수 있다. 한 번에 하나씩, 사람이 지켜보며 하는 걸 권한다.
- **Query** — 관련 페이지를 찾아 읽고 출처와 함께 답한다. 답은 마크다운·비교표·슬라이드·차트 등 여러 형태일 수 있다. **좋은 답은 위키에 새 페이지로 환원**한다 — 탐색도 원본처럼 쌓인다.
- **Lint** — 페이지 간 모순, 새 원본이 낡게 만든 주장, 고아 페이지, 자기 페이지가 없는 중요 개념, 빠진 상호참조, 웹 검색으로 채울 수 있는 데이터 공백을 점검하고 다음에 조사할 질문·찾을 원본을 제안한다.

**두 특수 파일**
- **index.md** — 내용 중심 카탈로그. 페이지마다 링크·한 줄 요약. ingest 때마다 갱신. 질의 시 먼저 읽는다. 원본 100개·페이지 수백 개 규모까지는 임베딩 검색 없이도 잘 돈다.
- **log.md** — 시간순 append-only 기록. 항목 머리를 `## [YYYY-MM-DD] ingest | 제목` 처럼 일정하게 두면 `grep "^## \[" log.md | tail -5` 로 최근 흐름을 바로 본다.

**원안이 일부러 열어둔 것**: 디렉터리 구조·스키마 관례·페이지 형식·도구는 도메인마다 다르다. 원안은 패턴만 전하고, 구체적인 형태는 사람과 LLM 이 함께 맞춰 가라고 한다.

## 이 스킬 묶음의 변형 (업무 폴더에서 검증된 형태)

| 원안 | 여기서는 | 왜 |
|---|---|---|
| `raw/` 폴더에 원본을 모은다 | **`raw/` 가 없다.** 기존 업무 폴더 구조 자체가 원본층 | 사람이 수년간 쌓은 폴더 구조가 이미 "찾는 길"이다. 원본을 `raw/` 로 옮기면 그 길이 끊긴다 |
| 원본을 넣으면 끝 | ingest 가 **배치**까지 한다 — 검증 → 관례에 맞는 폴더·파일명 → 위키 반영 | 원본층이 곧 사람의 폴더라서, 새 파일이 제자리에 놓여야 원본층이 계속 쓸 만하다 |
| index.md | index.md + **catalog.md** | index 는 위키 페이지 지도, catalog 는 원본 파일 인벤토리(폴더별·총계). raw/ 가 없으니 "원본이 무엇이 있나"를 catalog 가 맡는다 |
| 스키마 = CLAUDE.md / AGENTS.md | **CLAUDE.md** 의 `llm-wiki:begin … end` 블록. 기존 CLAUDE.md 가 있으면 내용을 보존하고 블록만 끼워 넣는다 | 코드 저장소·홈 폴더처럼 이미 CLAUDE.md 가 있는 곳에도 덮어쓰지 않고 세울 수 있다 |
| — | 스키마에 **세션 시작 규칙**(무엇을 하든 index → overview → log 부터) | 위키를 안 읽고 원본부터 뒤지면 쌓인 결론을 버리고 옛 정보를 다시 말하게 된다 |
| — | 스키마에 **폴더·파일명 관례 표** — ingest 가 새 관례를 만들면 추가 | 배치 판단의 기준을 위키마다 스키마에 둔다(스킬에 특정 위키 사정을 박지 않는다) |
| log 형식 | 같음 + 종류 확장(`setup`·`결정`·`수정`·`변경`) + 항목 본문에 판단 근거 | 다음 세션이 "왜 그렇게 됐나"를 log 에서 읽는다 |
