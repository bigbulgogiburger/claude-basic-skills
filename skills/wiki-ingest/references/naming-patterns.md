# 자료 유형별 폴더·파일명 일반 패턴

위키 스키마(`CLAUDE.md` 의 폴더·파일명 관례)에 해당 유형이 없을 때 읽는다. 여기 패턴은 **출발점**이다 — 실제 형제 폴더를 열어 보고 거기 패턴이 다르면 실제를 따르고, 새로 정한 관례는 스키마에 한 줄 추가한다.

실제 업무 위키에서 오래 버틴 패턴들을 일반화했다. `<갑>`·`<을>`·`<사업명>` 은 위키에 쓰인 정식 명칭으로 채운다.

## 계약

폴더: `계약관리/계약서/<연도>/<사업명>/` — 사업명 폴더는 계약명 그대로.

| 종류 | 패턴 | 예 |
|---|---|---|
| 작성본 | `계약서_<갑>_<을>_<사업명>.docx` | `계약서_A사_B사_시스템 고도화.docx` |
| **날인 완성본** | `[<갑>-<을>][完] <용역명>.pdf` | `[A사-B사][完] 시스템 고도화 용역.pdf` |
| 법무 검토본 | `[검토본]<원본명>_<YYYYMMDD>.docx` | `[검토본]계약서_A사_B사_시스템 고도화_20260727.docx` |
| PDF 변환본 | 작성본과 같은 이름 + `.pdf` | |
| 첨부서류 | `첨부서류/[<상대사>]<서류명>.pdf` | `첨부서류/[B사]사업자등록증.pdf` |

- 상대사 표기(약칭/정식)는 **같은 폴더 안 기존 파일과 통일**한다.
- 한 사업에 계약이 여러 건(원청↔하청, 하청↔재하청)이면 한쪽만 도착했을 때 나머지가 왜 필요한지(정산 근거 등)를 알린다.

## 견적·발주

폴더: `견적서/<연도>/<사업명>/`

| 종류 | 패턴 |
|---|---|
| 우리 표준 양식 | `(<우리회사>)01_견적서_<상대사>_<사업명>.xlsx` |
| 상대사 양식 본견적 | `(본견적)<상대사> 견적서_<사업명>.xlsx` |
| 상대사 양식 가견적(비교용) | `(가견적)<상대사> 견적서_<사업명>.xlsx` |

본견적은 선정된 1곳, 가견적은 비교용. 최저가가 본견적이 되는 게 보통의 선정 논리라 **금액 순위가 어긋나면 플래그**한다.

## 운영비·결제 증빙

클라우드·LLM API·SaaS 결제 영수증은 **서비스 운영 폴더 아래 `<서비스> 사용내역/`** 이 자연스럽다(예: `인프라/aws 사용내역/`, `인프라/LLM 사용내역/`).

- 파일명: `[<연도>]<내용>_<YYYYMMDD>.pdf` (날짜는 결제일) — 예: `[2026]AWS 사용내역_20260901.pdf`, `[2026]LLM API 크레딧 충전 100USD_20260729.pdf`
- 확인할 것: 청구 대상 **명의·주소가 이 사업 주체가 맞는지**(다른 법인 주소면 경비 귀속·부가세 공제 주체 문제), VAT 포함 여부, 원화 병기 시 환율 역산.

## 회의·보고

| 종류 | 폴더 | 패턴 |
|---|---|---|
| 회의록 | `회의록/` | `[YYYYMMDD] <상대> 회의록.docx`, 녹취록은 `… 회의록 녹취록.txt`, 초안은 `(초안)` |
| 주간·월간 보고 | `주간보고/` 등 | `<YYYY>-W<주차>_<월>월<N>주차.md` 또는 기존 관행 |
| 품의·결재 | `품의/`·`변경품의/` | `[<품의종류>]<제목>_<YYYYMMDD>.<ext>` |

## 산출물·납품

- 번호가 정해진 산출물 묶음(01 견적 → 02 계약 → … → 06 결과보고)은 **번호 접두어를 유지**한다: `04_수행계획서_<사업명>.pptx`.
- 판본은 `_v<N>` 접미. 날인·최종본은 `[完]` 또는 `_최종` 중 기존 관행 하나로.
- 증적 캡처 묶음은 `<번호>_증적_화면캡처_<YYYYMMDD>/` 폴더 + `<NN>_<화면명>.png`.

## 개인 위키(행사·이사·여행 준비 등)

주제 폴더(`예식장/`, `스드메/`, `하객/` 처럼)가 루트에 있고 `wiki/` 가 옆에 있는 구조가 흔하다.

- 파일명: `<YYYYMMDD>_<업체 또는 상대>_<자료종류>.<ext>` — 예: `20261012_A웨딩홀_견적서.pdf`
- 상담 메모·카톡 캡처처럼 원본이 대화면, 캡처는 주제 폴더에 두고 사실은 위키 페이지에 정리(출처: 캡처 경로 + 날짜).
- 두 사람이 함께 편집하면 충돌 사본을 조심한다(wiki-rules 함정 모음).

## 헷갈리는 폴더 판정법

이름만 보고 넣으면 틀리는 폴더가 있다. **열어서 실제 내용을 본다.**

| 이름 | 흔한 실제 용도 | 영수증·증빙을 넣으면? |
|---|---|---|
| `전표/` | 특정 전표 파일 몇 개 | ❌ 영수증 아카이브가 아닌 경우가 많다 |
| `세금계산서 서류/` | 상대사 통장사본·사업자등록증 | ❌ 세금계산서 자체가 아닐 수 있다 |
| `정산/` | 정산 작업 파일 | 맥락 확인 |
| `○○금액청구/` | 과금 기획·산정 자료 | ❌ 실제 청구서가 아닐 수 있다 |

판정이 끝나면 스키마의 관례 표에 "이 폴더는 실제로 무엇" 을 한 줄 남겨 다음 세션이 같은 함정에 빠지지 않게 한다.
