# 위키 작성 세부 규칙 · 실수 사례

위키의 `CLAUDE.md` 스키마가 기본 규칙이고, 여기는 **실제로 틀렸던 것들**을 모았다. 스키마와 다르면 스키마를 따른다.

## frontmatter

```yaml
---
type: entity | concept | source
updated: YYYY-MM-DD          # 반드시 이 형식. 내용을 고쳤으면 같이 올린다
sources: ["폴더/파일.pdf", "폴더/파일2.xlsx"]   # 근거 원본 경로 (위키 루트 기준)
---
```

허브(`index.md`·`overview.md`·`log.md`·`catalog.md`)는 frontmatter 없이 둬도 된다. 나머지는 3필드를 모두 갖는다.

**새 근거를 반영했으면 `sources` 에 경로를 추가한다.** 가장 자주 빠뜨린다 — 나중에 "이 서술 근거가 뭐지?"를 추적할 수 없게 된다. 원본이 아닌 근거(사용자 전언, 그룹웨어 화면 등)는 `sources` 대신 본문 출처 괄호에 적는다. `wiki_lint.py` 는 `sources` 의 경로가 실제로 있는지 검사한다.

## 앵커 (GitHub slug)

`scripts/slug.py` 로 계산한다. 손으로 짜맞추면 거의 틀린다.

규칙: ① 소문자화 ② `[\w\- ]` 밖 문자 제거 — **공백은 남긴다** ③ 남은 공백을 하이픈으로.

핵심 함정은 ②에서 공백이 보존된다는 것. 이모지·`·`·`—`·`|` 를 지우면 양옆 공백이 각각 하이픈이 되어 **하이픈이 연달아 생긴다.**

```
## 2. 자금·계약 구조 (3-tier) ⭐        → #2-자금계약-구조-3-tier-        (끝 하이픈 1개)
### 3-1. 견적서 — 비교견적 1:N          → #3-1-견적서--비교견적-1n        (하이픈 2개)
## [2026-09-14] 날인 | 🖋 **완료**     → #2026-09-14-날인---완료         (하이픈 3개)
### 6-4. CP 시트 (`pricing` 스킬)     → #6-4-cp-시트-pricing-스킬       (인라인코드 글자도 들어간다)
```

`·` 가 **글자 사이**면(`계정·권한`) 하이픈이 안 생기고, **공백과 함께**면(`계약 · 상세`) 생긴다. 같은 slug 가 두 번 나오면 두 번째는 `-1` 이 붙는다.

**제목을 고치면** 그 제목을 가리키는 모든 링크가 깨진다:

```bash
grep -rn "옛-앵커-일부" wiki/      # 참조하는 곳 찾기
python scripts/slug.py "새 제목"   # 새 앵커
python ../wiki-lint/scripts/wiki_lint.py wiki --quiet
```

## log.md

append-only. **맨 끝에** 추가한다. 기존 항목은 고치지 않는다 — 과거 판단은 그 시점 기준으로 옳았다. 틀린 게 밝혀지면 새 항목으로 정정한다.

```markdown
## [YYYY-MM-DD] <종류> | <한 줄 요약>
```

종류: `setup` · `ingest` · `query` · `수정` · `결정` · `lint` · `변경` (스키마에 다른 목록이 있으면 그걸 따른다). 이 머리 형식을 지켜야 `grep "^## \[" log.md | tail` 로 최근 흐름을 볼 수 있다.

**무엇을 쓰는가** — log 는 다음 세션이 진실원본으로 읽는다. 한 줄만 있으면 왜 그렇게 됐는지 몰라 같은 판단을 다시 한다. 값이 되는 것:

- 바뀐 수치는 전→후 대조 — `구값 → 신값 (사유)`
- 검증한 것과 방법 — "스캔 3p 렌더해 금액 3종 육안 대조"처럼 구체적으로
- ⭐ 부수 발견 — 작업하다 알게 된 것. 나중에 제일 쓸모 있다
- ⚠️ 미결 — 기한이 있으면 날짜와 함께
- 위키 반영 범위 — 어느 페이지 어느 절

항목 안 소제목(`### 미결`, `### 위키 반영`)이 매번 반복돼도 괜찮다 — 린터는 log 의 중복 제목을 문제 삼지 않는다. 다만 log 안 항목으로 앵커 링크를 걸 거면 slug.py 로 계산한다.

## catalog.md

### 헤더

총 파일 수와 갱신 이력을 헤더 blockquote 에 둔다. 새 이력은 **맨 앞에** 붙이고 이전 것은 뒤로 민다.

```markdown
> 최종 갱신: YYYY-MM-DD (ingest: **<무엇>** — <폴더> +N, 총 <이전>→**<이후>**) · 직전 YYYY-MM-DD (...)
```

총계를 고칠 때는 **무엇이 몇 개 늘었는지** 근거를 함께 적는다. 숫자만 바꾸면 다음 세션이 검증할 수 없다.

### 집계 규칙

- 제외 대상은 스키마의 catalog 절을 따른다(기본: `wiki/`, `CLAUDE.md`, `AGENTS.md`, Office 임시 `~$`·`.~lock`, 스킬·도구 폴더, LLM 산출물 폴더).
- 섹션은 폴더 단위: `## \`폴더명/\` — N개 · 용량`. 폴더를 신설했으면 섹션도 신설한다.
- 무효가 된 원본은 지우지 말고 `~~파일명~~ ⛔무효` — 실물이 디스크에 남아 있으므로 카탈로그에서 없애면 실제와 어긋난다.
- 아주 큰 폴더(교육 자료 수백 개 등)는 파일 대신 요약 등재해도 된다. 그때는 섹션에 "요약 등재"라고 적어 린터의 "파일명 없음" 경고가 정상임을 밝힌다.

## 상태 갱신 — 표와 문단을 함께

가장 흔한 실수: 아래에 새 문단만 추가하고 위쪽 표를 낡은 채로 두는 것.

```markdown
| # | 사업 | 벤더 | 상태 |
|---|---|---|---|
| 3 | 시스템 고도화 | A사 | 드래프트 |     ← 이걸 안 고치면 모순
...
(아래에) 3번은 B사로 교체되고 체결 완료됐다.   ← 새 문단만 추가
```

상태·벤더·금액이 바뀌면 그 값이 나오는 **모든 표·문장**을 찾아 고친다. 옛 값으로 `grep` 해 전수 확인하는 게 확실하다(`wiki_lint.py --stale-value "옛값"`).

## 이력 보존

```markdown
| 공급가 | ~~12,300,000~~ → **12,800,000** | 07-27 벤더 교체로 마진 재조정 |
```

취소선으로 구값을 남기면 "이 숫자 왜 이래?"를 추적할 수 있다. 다만 **본문 서술은 현재 값으로 읽히게** 쓰고 이력은 표나 註에 몰아둔다 — 본문에 취소선이 흩어지면 읽기 어렵다.

## 추정 vs 사실

원본에서 확인한 것과 추론을 구분한다(`(추정)`, `(사용자 전언 날짜)`). 자료끼리 충돌하면 ⚠️ 와 **양쪽 출처**를 남긴다. 나중에 실물로 판정되면 ✅ 로 해소 처리한다 — 이슈를 지우지 말고 해소 근거를 붙인다.

## 함정 모음

### 투명 PNG 를 다시 처리하지 않는다
도장·로고 PNG 가 이미 알파 채널을 갖고 있으면 배경 제거를 또 돌리지 않는다. 투명 영역의 RGB 는 보통 (0,0,0)이라 밝기 기준 로직이 그걸 불투명하게 되살려 **검은 사각형**이 된다. `extract.py` 가 코너 픽셀로 이미 투명인지 알려준다. 정리가 필요하면 `알파<8 → (255,255,255,0)` 과 크롭만 한다.

### 동기화 충돌 사본
Google Drive·Dropbox 로 여러 사람이 같은 위키를 편집하면 `… (○○님과 충돌하는 사본).md`, `… (conflicted copy).md` 가 생긴다. ingest 중에 보이면 **다른 작업보다 먼저** 알리고 `wiki-lint` 의 병합 절차를 따른다. 한쪽을 버리지 않는다 — 상대가 쓴 내용이다.

### Office 잠금 파일
`~$문서.docx`, `.~lock.문서.xlsx#` 는 열려 있는 문서의 잠금 파일이다. 배치·등재·추출 대상이 아니다. 원본이 열려 있으면 복사가 실패할 수 있으니 사용자에게 닫아 달라고 한다.

### Windows 경로
한글·공백·대괄호가 섞인 경로가 흔하다. 항상 따옴표, PowerShell 은 `-LiteralPath`(대괄호가 와일드카드로 해석되는 것을 막는다). Git Bash 에서 `D:\업무 문서` 는 `/d/업무 문서`. 260자 넘는 경로는 `\\?\` 접두가 필요할 수 있다.

### 같은 이름, 다른 파일
목적지에 같은 이름이 있는데 크기가 다르면 사람이 손으로 고친 판본일 수 있다. 해시를 비교하고, 다르면 덮지 말고 diff(`extract.py A B --diff`)를 보여준 뒤 선택을 받는다.
